# CLAUDE.md

Notes for Claude working in this repository.

## What this is

A client-side, single-page web app: an AI sandbox for building WebGL2 fragment shaders. No backend. TypeScript, no runtime framework. Builds to one self-contained `index.html` via `ts0`. See `README.md` for user-facing docs.

## Build / check

This project uses **pnpm 11** (not npm. Needs Node >=22.13), with a committed `pnpm-lock.yaml` and a `packageManager` field (`pnpm@11.9.0`) pinning the pnpm version. Enable it with `corepack enable`. pnpm-only settings live in `pnpm-workspace.yaml` (pnpm 11 no longer reads the `pnpm` field of package.json). `allowBuilds` lists the deps permitted to run install scripts (ts0. Esbuild is denied), the successor to pnpm 10's `onlyBuiltDependencies`.

```sh
pnpm install
just typecheck    # tsc --noEmit over src + test
just build        # ts0 build -> dist/index.html
```

- This is a **Node/TypeScript** project. Do NOT apply `go-toolchain` here.
- ESM only. Use `.ts` extensions in relative imports (required by ts0/esbuild).
- The bundle ships as one self-contained `index.html` with **no external requests**. (There is no bundle-size budget — do not optimize for byte count.)

### `ts0.json` vs `tsconfig.json` (they are not redundant)

- `ts0.json` configures the **bundler** (entry, outdir, target, format). ts0 is the only thing that reads it.
- `tsconfig.json` configures **our own** `tsc --noEmit`, which the editor/IDE and `just typecheck` use. Its `include` is `["src", "test"]` — leaving `test` out hides real errors in the test files, which is how three of them survived. ts0 does NOT read it: `ts0 build`/`ts0 test` generate their own tsconfig from `ts0.json` and type-check first (and reject explicit `any` on top of `strict`), so CI's type safety comes from ts0. This file keeps the local check honest with it. Do not delete it.
- Keep the code `node --experimental-strip-types`-clean (no TS parameter properties etc.) so the modules can be exercised by scripts of the plain Node test.

## Architecture

- `src/gl/` — `Renderer` is a **multi-pass, multi-LAYER** WebGL2 renderer. The document is a back-to-front stack of layers. Each layer is its own graph of passes (each pass renders to its own offscreen, ping-ponged texture, run in topological order `topoOrder` of channel→pass deps, a channel pointing at its own pass = feedback). Layers render bottom-up. Each layer sees the composite of every layer below as its **`under`** input.

  Its own rasterized geometry as its **`geometry`** input, and its optional mask as **`mask`** (channel `kind`s resolved per-layer, NOT graph edges). The layer's output pass is the new composite, and the topmost visible layer's composite is blitted to the screen by an internal present shader. A layer may carry a **mask** (`Layer.mask`, itself a layer rendered standalone with no `under`).

  `add_mask` adds a visible `Masked Composite` graph pass on the owner layer that samples `under`, the unmasked output pass, and `mask`, then computes `mix(under, composite, mask.a)`. `reconcileLayer` reconciles stack layers AND their masks (recursively). `present` takes a texture. `setDocument()` ((re)compiles + reconciles every layer/pass, returns a per-pass `CompileResult`) replaces the old `setPasses`. `setLayerShapes`/`setLayerProps` are cheap per-layer updates (no recompile).

  **Geometry is real instanced meshes**: `geometry.ts` (`GeometryBatch`, `drawArraysInstanced` of a unit quad per shape, premultiplied "over") shaded by a per-kind SDF in `shape.vert/frag.glsl`. The shape registry `shapes.ts` is the single source of kinds (array order = the shader's `kind` switch index, so a new primitive is one entry + one `case`). Targets are `rgba8` or `rgba16f` (HDR, when `EXT_color_buffer_float`/`OES_texture_float_linear` allow, else it falls back). `connect*Input`/`disconnectInput` bind inputs (`connectAmbientInput` for under/geometry/mask). `maxInputs()` exposes the GPU texture-unit ceiling.

  Channels can be **dynamic** (uploaded video / live webcam). A `DynamicTexture` (`dynamictexture.ts`) owns a `<video>` whose current frame is re-uploaded every render tick (texImage2D then texSubImage2D), follows play/pause/reset. It stops its stream on teardown (`connectVideoInput` / `connectWebcamInput`. `setInputParams` changes filter/wrap without reloading. `dynamicKey()` lets the store skip redundant reloads).

  It also owns the clock, uniforms, and screenshot (average-colour feedback. The default screenshot encodes **WebP** now, smaller than JPEG, and derives `mediaType` from the bytes `toDataURL` actually produced). `captureFloat`/`hasFloatOutput` read the presented composite back as raw half-float RGBA (`readPixels` with `HALF_FLOAT`, flipped top-down) when the output pass is `rgba16f`, for lossless HDR/EXR export. `readViewport`/`readPass` read RGBA bytes for histograms, and `nextFrame` waits for a presented frame so `capture_screenshot` sees every earlier edit. Tool screenshots render at a fixed 1280x720 before scaling (`captureOffscreen`). The window cannot change their aspect.

  `wrapper.ts` assembles the full GLSL ES 3.00 source around the user's `mainImage` for a pass, declaring exactly that pass's `iChannel0..N-1` + `iChannelResolution[N]` (channel count is a parameter. Inputs are not capped at four) and emitting `#line 1` so compile errors map to user line numbers. Custom `uniform float/vec2/vec3/vec4 u_name;` lines in the body are the source of truth: `extractUniformDeclarations` reads them (so they become live controls).

  `assembleFragment` hoists them into the header (deduped — never a `redefinition`) while stripping them from the body. The declaration may carry an **optional precision qualifier** (`highp`/`mediump`/ `lowp`) and an **optional `= <default>` initializer** (numeric literal or `vecN(...)` constructor, single-arg splat) — `parseInitializer` seeds the control's starting value. `rangeForValues` widens the slider to fit a baked default outside 0..1. Float literals may carry the GLSL ES 3.00 single-precision `f`/`F` suffix (`= 40.0f`, `vec3(1.0f, …)`).

  `glslLiteralToNumber` strips it before `Number()` so an idiomatic baked default no longer silently parses to 0. The header re-declares the uniform WITHOUT the initializer (GLSL ES requires that). A **trailing `//` or single-line `/* */` comment after the `;` is tolerated** (a natural thing to write that used to silently break both extraction and stripping). `reconcileUniforms(declared, previous, lastDefaults)` is the pure helper the store uses on every recompile to fold the source-declared set into the live control list.

  A NEW uniform takes its baked default, an UNCHANGED initializer preserves the live slider/`set_uniforms` value, and a **CHANGED initializer is adopted** (editing `= 1.5` -> `= 2.0` actually takes effect instead of being silently preserved at the old value — the store remembers each uniform's last-seen declared default in a session `declaredDefaults` map to tell the two apart, reset on project switch / undo so those preserve persisted values). `textures.ts` (procedural built-ins).
- `src/ai/` — `providers.ts` translates the neutral conversation model to/from **Anthropic Messages** and **OpenAI Chat Completions** (both streamed, vision + tool use. `testConnection` + `listModels` power the Settings test button and model combobox). It sets prompt-cache breakpoints and returns per-response token `Usage` + generation time. `agent.ts` runs the tool loop (and forwards `Usage` via the `onUsage` callback).

  `system-prompt.ts` exposes `buildSystemPrompt()` (the stable, cacheable base — it does NOT list tool schemas, those go in the request's `tools` field for native models) and `buildProjectState()` (the volatile per-edit project state, kept OUT of the cached prefix and sent as a trailing message — it includes the **live GLSL source of each layer's OUTPUT pass** so the model edits against ground truth without a `read` round-trip and sees any edits the user made between turns) plus `textToolInstructions` for text mode.

  `pricing.ts` maps a model id to its rates + context window for the chat cost / context indicator. `compact.ts` is conversation **compaction**: `summarizeConversation` asks the model (no tools) to "summarize this entire conversation in detail for a future instance of yourself to pick up". `buildCompactedMessages` replaces the whole history with that recap as a valid `user(request)`→`assistant(summary)` round (both flagged `compaction` on the `Message`), freeing the context window. Pure helpers (`shouldCompact`/`hasCompactionSummary`/`buildCompactedMessages`) are unit-tested in `test/compact.test.ts`.

  The store owns `compactConversation(signal)` (summarize-and-replace + persist). The chat drives it with its own busy/abort, exactly like an agent turn (Stop cancels it, and a mid-stream cancel does NOT replace the conversation).
- `src/ai/tools/` — **one tool per file**, each colocating its JSON-schema `def` and `execute`, self-registering into `registry.ts`. The store builds a `ToolContext` (the only surface a tool may touch) and dispatches via `getTool`. `toolDefs({ imageGen })` gates the offered set. The surface is **generic and parameterized** — there is **no "active" layer/pass for tools**. Every tool targets its object by an EXPLICIT ref in the call. A **layer ref** = name | id | stack index (0 = bottom/back, omitted = the top layer), a **pass ref** = name | id within a layer (omitted = its output pass), a **shape ref** = index within a layer. `ctx.resolveLayer(ref)` / `ctx.resolvePass(layer, ref)` / `ctx.resolveShape(layer, i)` are the uniform resolvers (the store keeps `selectedLayerId`/etc. only for the **human UI editor**. Tools never read it). The **tools**:
    - **read** `{what: pass|graph|passes|layers|shapes|assets|uniforms, layer?, pass?}` — the one inspection tool (`describe.ts` formats it). Replaces `get_shader` + every `list_*`.
    - **create_object** `{type: layer|pass|shape|mask, layer?, …}` — add a thing (adding a child names its parent `layer`). A `type:pass` with a `name` ADDS a pass. With NO name it AUTHORS the layer's output pass from `source` (the old `init_shader` — refused once the pass is authored, via `ctx.isOutputUnauthored`. It cannot overwrite real work. This replaces the old `allowInitShader` turn-gating with an execution-time check so the tool set stays byte-stable).
    - **destroy_object** `{type: layer|pass|shape|mask, layer?, pass?, shape?}` — the store guards stay (cannot remove the only layer/pass. Removing a pass clears channels referencing it).
    - **edit_object** `{type: layer|pass|shape|project, …}` — change PROPERTIES (not source): layer name/visible/opacity/output_pass/order|move, pass format, shape transform/colour, project name. Only `type:project` is permission-gated.
    - **edit_shader** (forgiving exact-snippet replace. Optional `layer`/`pass`), **connect_pins** (graph wiring. Optional `layer`. `from: none|under|geometry|mask|builtin:<name>|pass:<name>|webcam|asset:<name>`. Input pins are inferred from `iChannelN` references), **set_uniforms** (shared across ALL layers. A **PATCH** that merges by name — omitting one never resets it), **capture_screenshot**, **histogram** (viewport or a pass buffer, by channel), **generate_texture** (the lone gated tool — the stable per-session image-gen setting). `geometry_util.ts` parses shape fields (degrees→radians, rgba). `describe.ts` formats read output. The advertised set is **byte-stable across a whole conversation** (only `generate_texture` is conditional, on the stable per-session `imageGen` flag), so the prompt-cache prefix never shifts mid-conversation.
- **Permission-gated tools**: a tool sets `requiresPermission` to `true` OR to a **predicate** `(input) => boolean` (+ an optional `permissionPrompt(input)`). Before running a gated call the agent loop awaits `cb.requestPermission(...)`. The chat UI renders an Approve/Deny card (Stop counts as deny) and a denial is fed back to the model instead of executing. `edit_object` is the user: its predicate gates only `type:project` (the shader rename, via `ctx.renameProject`), not layer/pass/ shape edits. Works in both tool modes (the gate lives in the shared execute loop).
- **Tool modes** (`chat.toolMode`): `native` uses the provider's function-calling API. `text` (for models/endpoints without it) describes the catalogue. As forgiving XML tags (`textToolInstructions`, keyed by `TOOL_NAMES`), parses them out of the reply (`texttools.ts`), and feeds results back as a plain user message. Most tags carry JSON. `edit_shader` and `create_object` (when it carries GLSL) use sub-tags so raw GLSL needs no escaping. The advertised/described set is same every turn (no per-turn drop-out).
- `src/state/` — `types.ts`: a `Project` is a **layer stack** — `layers: Layer[]` drawn back→front. Each `Layer` has its own `passes: Pass[]` + `outputPassId` (its composite) **plus** `shapes: Shape[]` (geometry), and `visible`/`opacity`. A `Pass` has `source`, a variable-length `channels: Channel[]` (up to `MAX_INPUTS`), and `format` (no stored graph position — the Passes view auto-lays the DAG out from its edges, see `ui/graphlayout.ts`). A `Channel` `kind` is `none|under|geometry|mask|builtin|pass|video|webcam` (`under`/`geometry`/`mask` are layer-ambient — no extra fields. `pass`+`passId` is a same-layer edge).

  A `Shape` is `{kind, x, y, w, h, rotation, color, cornerRadius, feather, falloff}` in normalized 0..1 canvas coords (`falloff` 0..1 ramps alpha centre->edge = a radial gradient). A layer also has an optional `mask?: Layer` (an owned layer used as a per-pixel opacity mask). `makeCompositeLayer` builds a ready "over" layer, `makeMaskLayer` a geometry-passthrough mask. `ensureMaskCompositePass` adds the graph node.

  That node applies it (tagged `Pass.role = "maskComposite"`, which is how it is recognised on reload and removal, not by name or source. An edited wrapper is not wrapped again. Its wiring) tags a pre-`role` save. `LAYER_COMPOSITE_SOURCE`/`MASK_SOURCE`/ `MASK_COMPOSITE_SOURCE` are their default shaders. `src/util/media.ts` holds the file/webcam plumbing plus `sanitizeAssetName` (folds exotic whitespace like U+202F — macOS screenshot filenames — to a plain space and drops zero-width/bidi marks, applied at upload so assets stay referenceable by their plain-looking name).

  `src/util/exr.ts` is a minimal dependency-free OpenEXR writer (single-part scanline, NO_COMPRESSION, HALF channels) used to export an `rgba16f` render losslessly. Pure + DOM-free, unit-tested in `test/exr.test.ts`.

  `store.ts` (single owner of state + the renderer + persistence + `applyTool` + undo/redo) tracks `selectedLayerId` + `selectedPassId` + `selectedShapeId` (the active layer can be a layer's mask — `layerById`/`passById`/`eachLayer` recurse into masks) and exposes layer mutations (`addLayer`/`removeLayer`/`reorderLayer`/ `setLayerVisible`/`setLayerOpacity`/`renameLayer`/`selectLayer`/`addMask`/ `removeMask`), shape mutations (`addShape`/`updateShape`/`removeShape` — cheap via `renderer.setLayerShapes`), and the per-layer pass-graph mutations (`addPass`/`removePass`/`setOutputPass`/ `setPassSource`/`connectPin`/…, all resolving the pass's owning layer), plus `commitMessages()`.

  `defaults.ts` `normalizeProject` migrates BOTH eras — legacy single-`shaderSource` and the mid-era flat `passes`/`outputPassId` graph — into a single "Base" layer (tested in `test/layers.test.ts`). `persist.ts` (IndexedDB, normalizes on read). `history.ts` (generic, DOM-free snapshot undo/redo stack).
- **Undo/redo**: `history.ts` is a generic `History<S>` (stacks of `{snapshot,label}`, coalescing by tag + time window, reference-counted grouping, a size cap, an `onChange` callback). The store owns a `History<ProjectSnapshot>` over the undoable project slice (`name`, `layers`, `uniforms` — NOT messages/ids). Each mutating store method calls `this.commit(label, tag, coalesce?)` after mutating. `applySnapshot` restores + re-renders (it emits a `"restore"` event so the code editor refreshes even while focused). Typing and slider drags coalesce. An **agent turn is one undo step** via `beginHistoryGroup`/`endHistoryGroup` (the chat wraps `runAgent`). History resets on project switch (`adoptProject`) and is gated off while `busy`. The store emits `"history"`. The topbar renders Undo/Redo buttons and `app.ts` binds Ctrl/Cmd+Z and Ctrl/Cmd+Shift+Z / Ctrl+Y (deferring to native undo inside text fields). Unit-tested in `test/history.test.ts` (`pnpm test`, run by CI).
- `src/ui/` — vanilla-DOM components via the `el()` helper in `src/util/dom.ts`. The chat (`chat.ts`) shows hover **edit/delete** actions on user prompts and assistant replies.

  It delete removes a whole conversation round, edit rewrites a user prompt then re-runs from there (forking the conversation). The typed **`/compact`** command (parsed in `send()`, shown in the input placeholder) summarizes the whole conversation and replaces it with one collapsible "Conversation compacted" card (the `compaction` summary message), freeing context. **Steering**: the input stays live while a turn runs. A message sent mid-turn is queued (rendered immediately).

  And folded into the conversation by the agent loop on its next step rather than starting a second turn. `runAgent` drains the queue via the `takeSteering` callback at the top of each iteration AND before it will stop (so a steer can keep a finishing turn going). Injection only happens at "balanced" points. It never splits a `tool_use` from its `tool_result`. Stop discards un-picked-up steering, the chat re-runs once for the rare message queued in the last iteration.

All embedded into the single-file bundle by ts0's fetch interceptor and loaded at runtime via `fetch(new URL(...))` (the shader sources are passed into the `Renderer` constructor as a `RendererShaders` object).

## Provider gotchas (verified against the claude-api skill)

- Default chat model is `claude-opus-5`.
- **Claude 4.7 and newer rejects `temperature`/`top_p`/`top_k`** (Opus 5, Sonnet 5, the Fable family). `providers.ts` gates by an ALLOWLIST of the old budget-thinking models (`ANTHROPIC_BUDGET_MODELS`) plus 4.6. An unrecognised id is treated as new: adaptive thinking, no temperature. `anthropicBody`/`openaiBody` are exported and pinned in `test/providers.test.ts`.
- Hosted OpenAI reasoning models (`o*`, `gpt-5*`) take `max_completion_tokens` and no `temperature` (`isOpenAIReasoningModel`). Compatible servers keep the classic fields whatever the model id. An unset `maxTokens` or `temperature` is omitted, so the provider's default applies.
- Compaction sends the same `tools` as the agent turns with `tool_choice: none` (`StreamOptions.toolChoice`). A history holding tool blocks 400s without them.
- Anthropic browser calls require `anthropic-dangerous-direct-browser-access: true`.
- **Providers** are a registry, `PROVIDERS` in `state/defaults.ts`: `label`, `wire` (`anthropic` | `openai` — everything but Anthropic speaks Chat Completions), `baseUrl`, `needsProxy`, `needsKey`, `needsKeyForModels`, `models`. Adding one is an entry plus a `ProviderId` member. The dropdown, the base-URL fallback, the key guard and the model combobox all read it. Shipped: anthropic, openai (generic/self-hosted), openrouter, ollama-cloud.
- **Bifrost** uses both wires, with no registry entry of its own. The OpenAI wire takes base URL `http://localhost:8080/v1`. The Anthropic wire takes `http://localhost:8080/anthropic`. A base-URL override adds `x-bf-vk` alongside the normal credential header (`openaiAuthHeaders`, `anthropicHeaders`). The hosted defaults keep their current headers. A direct browser call needs `x-bf-vk` in Bifrost's `allowed_headers`.
- **OpenAI-wire reasoning** is captured from `reasoning`, `reasoning_content`, and `reasoning.text` entries of `reasoning_details` (`reasoningDelta`). It is replayed as `reasoning_content` plus a signed `reasoning_details` entry (`toOpenAIMessages`). Anthropic thinking blocks keep their leading position and signature.
- **Chat keys are per provider** (`chat.apiKeys`). `mergeSettings` moves a legacy `chat.apiKey` into its provider's slot. `chatApiKey` reads the active one. The OpenRouter redirect stores the live Settings form in `sessionStorage` and restores it on boot.
- **OpenRouter sign-in** uses PKCE (`ai/openrouter.ts`). Settings stores the verifier and a settings draft in `sessionStorage`. The boot path restores the draft, exchanges a `code`, and cleans the URL (`completeOpenRouterSignIn`). A failure leaves the stored key alone and shows a banner.
- **`needsProxy` forces the proxy on regardless of the toggle** (`chatUsesProxy`), because Ollama Cloud answers with no `access-control-allow-origin` and a browser cannot read a direct reply. Settings ticks the visible box and says why. It is stated rather than hidden. `chatEndpoint(settings)` composes base + path + proxy and is the place any chat URL is built.
- **CORS proxy setting is a TEMPLATE** (`util/misc.ts` `proxied()`): `{{.url}}`
  takes the percent-encoded target, `{{.rawurl}}` the target verbatim, and a
  token-less value has the target appended (the older prefix form). Encoding matters — an unencoded target carrying `?` or `&` becomes the PROXY's parameters. Getting proxy.pazer.ai's shape incorrect is silent: it answers 200 with a usage page that `testConnection` reads as a success. `migrateProxyTemplate` (in `mergeSettings`) rewrites a pre-template saved value into the explicit template that reproduces what it used to do. Pinned in `test/proxy.test.ts` and `test/providers.test.ts`.
- Extended thinking is **on** for Anthropic, model-gated in `providers.ts` (`anthropicThinking`). A token `budget` for the 4.5-era allowlist, and `{type:"adaptive", display:"summarized"}` for everything else, unrecognised ids included (every model since 4.6 takes adaptive). A budget model needs an explicit `maxTokens`. Without one no thinking is sent. Thinking and `temperature` are mutually exclusive in the request. Thinking blocks are captured off the stream (`thinking_delta` + `signature_delta`), stored on the assistant `Message` as `ThinkingBlock`s. Thinking blocks replayed **first** in `anthropicContent` — required, or tool-use continuations 400. The chat UI streams the summary into a collapsible `.thinking` block.
- `output_config.effort` is set to `medium` (`anthropicEffort`). It 400s on Sonnet 4.5 / Haiku 4.5 / Opus 4.1 and older. Those are denylisted and every other id gets it (the server default is `high`).
- Anthropic SSE events handled: `message_start` (usage), `content_block_start/delta/stop` (text, thinking, signature, tool input deltas), `message_delta` (stop_reason + output tokens), `error`. OpenAI: `choices[].delta.content` / `.tool_calls[]`, `finish_reason`, and the last `usage` chunk (we send `stream_options.include_usage`).
- **Prompt caching**: Anthropic requests carry `cache_control: {type:"ephemeral"}` on the `system` block (covers tools + system, both stable) and on the last conversation block (caches the growing history). The per-request **project state must stay out of that cached prefix**. It rides as a trailing user message (`buildProjectState`) so editing the shader does not invalidate the cache every turn. Hosted OpenAI has no per-message marker — caching is automatic server-side for prefixes many tokens. The trailing-state layout keeps the prefix stable, and we send a stable per-conversation `prompt_cache_key` (`shadertoy-<projectId>`, threaded via `StreamOptions.cacheKey`) for cache-hit routing. Self-hosted / compatible endpoints (any non-hosted base URL — `isHostedOpenAI`) additionally get `cache_prompt: true` to opt into KV-cache prefix reuse (llama.cpp et al.), do not sent to hosted OpenAI/Azure. This is which 400 on unknown fields. Anthropic breakpoints/request (max is 4), ephemeral 5-min TTL.
- **Usage accounting is server-truth only — never estimated.** The **% cached** indicator and the spend figure come *exclusively* from the token counts the endpoint reports. The app does not estimate or infer either from the prompt prefix or anything else. `Usage.cacheReadTokens`/`cacheWriteTokens` are **tri-state** (`number | undefined`): a number (including an explicit server-reported `0`) is a real count, while `undefined` means the endpoint omitted cache info fully (e.g. Ollama/local OpenAI-compatible servers). Anthropic's `input_tokens` already *excludes* `cache_read_input_tokens` and `cache_creation_input_tokens` (so the three sum to the full prompt — nothing to subtract). OpenAI's `prompt_tokens` *includes* cached tokens. The uncached remainder is `prompt − cached`. `pricing.ts` `cachePct(usage)` returns the cache-hit % (undefined when the server omitted the count) and `messageCost(model, usage)` prices each class at its published rate. Base input × in-rate, `cache_read` at the read discount (≈0.1× base for Anthropic), `cache_creation` at the write premium (1.25× base for the 5-minute ephemeral cache), output × out-rate. It summed, not double-counted. A cache-WRITE turn is therefore billed at the write premium, not the read discount. The server-reported `usage.cost` (OpenRouter) wins when present. The local table is the fallback, and no cost is shown when neither exists. The pure helpers are unit-tested in `test/cache.test.ts`.
- The chat panel shows a usage indicator (tokens/sec, context %, **% cached** — shown only when the server reported a cache-read count, including an explicit 0. Hidden ("n/a") when omitted — cost this turn + session). `Usage` is captured per response, cost/context come from `pricing.ts` (tokens-only when neither the server nor the table gives a cost).

## CI / deploy

`.github/workflows/ci.yml` is the only workflow. It holds **three actions and no `run:` steps**: `actions/checkout`, `wow-look-at-my/ts0@master`, then `buildhost/.github/actions/buildhost-publish-site@master` publishing `dist/` as a **public** per-branch site (`public: "true"`) via GHA OIDC.

The ts0 action takes **no command input**: one step always type-checks, tests and builds, in that order. A caller cannot pick a cheaper subset. A green check means the whole thing ran. Passing `args:` fails the step.

There is no node/pnpm setup because none is needed: `ts0.cjs` carries its own TypeScript compiler. This project is browser-target with zero runtime dependencies, so it builds and tests from a bare checkout. The trade is that CI no longer validates `pnpm-lock.yaml` — `pnpm install --frozen-lockfile` is a local-only check now.

`branch: ${{ github.ref_name }}` goes in unmodified. buildhost resolves a
slash-named branch by longest match against its own site rows (`splitSiteBranch`, and `validSiteBranch` permits `/`), so `claude/foo` needs no slug.

The job needs `deployments: write` (publish-site always registers a GitHub Deployment, no opt-out), `artifact-metadata: write` (it also records the upload on the org's linked-artifacts page. A refused record fails the publish with HTTP 404) and `pull-requests: write` (it comments the preview URL on the branch's pull request. A refused lookup fails the publish with HTTP 403. The only opt-out is `comment: "false"`), plus `actions: read` + `checks: read` (its embedded no-all-builds-job guard scans the run's jobs and check runs), alongside `id-token: write` for OIDC.
